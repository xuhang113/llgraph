# 2026-09-14 扩散式检索：同一 pattern 别再按目录逐个搜

选题：**性能（无效工具调用 / 往返浪费）**。这条切口被 `2026-09-10`、`2026-09-12`、
`2026-09-13` 连续三轮结尾点名：

> 「**性能**里还没碰过的『无效工具调用』——同一问里 grep 同一 pattern
> 只换 `path` 的扩散式检索。」

本轮做完它。顺带修了一个下手量数据时撞到的真 bug（见第 2 节），
它和本层是同一条链路上的，不修的话本层的收益会被它抵掉一半。

## 为什么是这个切口

先量再改。同机、真 `ToolNode` + 真 `grep_files`，问题是「哪些模块用了
`resolve_context_settings`」（本仓真实命中 **14 个文件、散在 5 个包**）。
模型不知道命中散在哪，按包名顺序逐目录搜：

| 「拿到全部 14 个命中文件」 | 改前 | 改后 |
|---|---|---|
| LLM 往返 | **7 轮** | **3 轮** |
| 真实执行的 grep | 7 次 | 3 次 |
| 模型看到的工具正文 | 12932 字符 | 13446 字符 |

省的不是 token，是**往返**。每一轮往返都要把整个会话重新出站一次
（`2026-09-10` 那轮量过：压缩点之后的内容全价重算 + 重新等 TTFT），
所以 7 → 3 轮省下的是 4 次全 prompt 计费与 4 次首 token 等待。
正文反而多了 4%——扩根后的那一条更密（一次给出 14 个文件的完整表），
换来的是模型第 3 轮就有了完整答案，不必再猜「还有哪个包没搜」。

`tool_loop_guard` 原有的覆盖判定只认「新根被旧根包住」（旧根 `.` 或父目录），
兄弟目录之间互不覆盖，所以扩散式检索一路都是真执行，一次也拦不下。

## 做了什么

### 1. 攒够就扩根，不是拦掉（`core/search_diffusion_guard.py`，新）

刻意**不做**「拦下来让模型自己改参数」：那样要多花一次往返才回到正题。
本层直接把这一次调用**改写到公共祖先执行一次**：

- 触发条件：同 `pattern` + 同 `file_glob` 已经搜过 `grep_widen_after`（默认 2）个
  **互不覆盖**的根，本次又换到一个谁也不覆盖谁的新根 → 扩到三者的最近公共祖先
  （没有共同前缀就是工作区根 `.`，这也正是 prompt 里一直建议的一次 `path="."`）。
- 改写只发生在**执行时的调用副本**上，原 AIMessage 里模型请求的参数一个字不动
  （Trace / 会话回放仍是模型的真实意图，已固化成用例）。
- 结果尾部追加一行 `[llgraph] 检索已扩根: path="X"`，说明「本次真正搜的是 X，
  覆盖你逐个搜过的那几个目录，别再按子目录搜同一 pattern」。

**尾注是刻意追加在末尾、不是前置的**：`is_llgraph_placeholder` 按开头判占位，
前置会让整条结果不进历史索引——那样后续的覆盖短路就全没了
（变异验证里把它改成前置，两个用例立刻挂）。

### 2. 后续的子目录搜索交给已有的覆盖短路

`build_history_index` 建索引时，grep 的 `path` 改为按**真正搜过的根**记
（从上面那行尾注解析）。于是第 4、5、6 次同 pattern 的子目录搜索
不用本层再写一遍判定，直接命中 `tool_loop_guard` 已有的
`_path_covers` 短路，返回短指针。

`fp`（精确去重键）仍按**模型请求的参数**建：它标识「模型要了什么」，
同参数原样重发照旧精确命中。

### 3. 同一批 fan-out 也只搜一次

模型有时把 4 个只换目录的 grep 塞进同一条 assistant 消息。这时往返只有一次，
但 4 次 ripgrep + 4 张命中表都是白费。本批内第 3 个触发扩根，
其余被扩根覆盖的直接合并到它（占位以 `[llgraph]` 开头，不进历史索引）。

扩根那一次自己被拦下时（比如同参数上一次失败过）会**撤回**扩根决策、
也不再合并后续调用——否则占位会指向一条根本没跑的结果。

### 4. 顺带修：`grep_files(path=<单个文件>)` 一律回「未找到匹配内容」

量数据时撞到的：`rg` **只给一个文件参数时默认不打印文件名**，
输出是 `3` 而不是 `path:3`、是 `12:code` 而不是 `path:12:code`。
llgraph 三处解析全都指望有路径前缀，于是：

- `ripgrep_count` 解析出空 → `grep_files(pattern=..., path="a/b.py")`
  **永远**返回「未找到匹配内容」，还附一句「禁止同 path 重复 grep」。
  模型据此下「这个符号不在这个文件里」的错结论——而单文件 grep 是明确支持的用法
  （python 兜底路径里专门有 `scan_root.is_file()` 分支）。
- `ripgrep_content_in_files` 解析出空 → 命中只落在**一个文件**时，结果里
  一条正文都没有，只剩「显示 0/N 处 … 还有 N 处未列出」，模型必须再补一轮 read。

三处 `rg` 调用补 `-H`。这一条和本轮主题是同一件事：扩根之后命中常常集中在
少数文件，不修的话省下的往返又被「没有正文，再读一轮」吃回去。

### 配置（有默认值，不配也能跑）

```json
{ "agent": { "grep_widen_after": 2 } }
```

`0` / `false` 关闭本层；受 `agent.identical_tool_guard` 总开关约束
（总开关关掉时扩根表一并清空）。

## 怎么验收

回归测试断的是**「什么时候不许扩根」**，不是文案：

- 不到阈值（只搜过 1 个目录）→ 不扩根
- 本次根已被旧根包住（历史搜过 `.` 或父目录）→ 不扩根，交给已有覆盖短路
- 模型自己已经改成搜父目录 → 一个字不改它的参数
- 新根盖住了部分旧根，剩下互不覆盖的不到阈值 → 不扩根
- 不同 pattern / 不同 `file_glob` 分别计数，互不串味
- 算出的祖先在磁盘上不是目录（模型给的相对路径可能被工具内部改写过）→ 不扩根
- 无共同前缀 → 扩到 `.`；`./a/b` 与 `a/b/` 归一成同一个根
- 扩根那次自己被拦下 → 撤回决策，且不合并后续调用
- 扩根结果失败（路径错）→ 不给任何覆盖，下一次照常真执行
- `read_file` / `glob_files` 不受影响；`grep_widen_after=0` 时整层不生效

**变异验证**（12 处逐个退回，对应用例必挂）：阈值退成 1、不跳过已被旧根覆盖的调用、
不校验祖先是目录、不排除被新根覆盖的旧根、尾注前置、pattern/file_glob 不分组、
历史索引不认扩根后的真实根、被拦下的扩根决策不撤回、扩根被拦后仍合并后续调用、
以及三处 `rg` 各自去掉 `-H`。

手工 / 端到端：

- 真 `ToolNode` + 真 `grep_files` 走生产链路（已固化成用例）：第 3 次执行的是公共祖先、
  一次拿齐 4 个包，第 4 次不再执行真实 grep；原 AIMessage 的 `path` 未被改写
- 上面那张 7 轮 → 3 轮的表（脚本在本轮临时目录里，未入库）
- 单文件 grep：`grep_files(pattern="def grep_files", path="llgraph/core/filesystem_tools.py")`
  改前「未找到匹配内容」，改后「1 处 / 1 个文件」并带上下文
- `python3 -m pytest tests -q` → **700 passed, 3 skipped**（本轮前 665 + 新增 35，
  本机未装 `[index]` 可选依赖，3 skip 与基线一致）

## 未做 / 下一步不要做

- **不要**把默认阈值调成 1（搜第 2 个目录就扩根）。第 1、2 次窄搜给的是**逐行正文**，
  扩根后的结果在命中多时会被 `grep_collapse` 折成文件表；阈值 2 的意思是
  「让模型先拿两段细节，再给它全局视图」。真要更激进，先量「折叠后模型是否还需要补读」。
- **不要**把本层推广到 `glob_files` / `search_code_semantic`。glob 的结果是文件名列表、
  语义检索的结果依赖索引状态，扩根的收益与风险都和 grep 不是一回事；
  真要做请先量 glob 扩散的真实占比。
- **不要**改 `[llgraph] 检索已扩根: path="X"` 这行的形态。它同时是给模型看的说明和
  历史索引的判据（`widened_root_from_result` 按它解析），改文案等于改协议。
- **不要**把尾注挪到结果开头，也**不要**把合并占位改成不以 `[llgraph]` 开头。
  前者会让扩根结果不进历史索引，后者会让占位被当成真结果建立虚假覆盖。
- **不要**为了「更准」在扩根前先跑一次试探性 grep 估算命中量。那等于把省下的
  ripgrep 又花回去，而且两次搜索之间工作区可能已经被写工具改过。
- **不要**用 `mcp<2` 式的思路去「修」`-H`（例如钉某个 rg 版本）。`-H` 是 rg 的稳定行为，
  显式传比依赖默认值对。
- 下一轮建议（二选一）：
  - **商用体验 / 改码命中率**：`search_replace` 前是否该强制带目标段真实行号。
    `2026-09-09` 起连续四轮点名，仍未做。注意 `edit_apply` 已有六层容错，
    先量「剩下的失败里有多少是行号能救的」再动手。
  - **性能**：`format_duplicate_block` 的「上次返回摘录」上限 900 字符。
    扩散式检索被短路后，模型看到的占位里有大半是重复摘录（本轮实测每条 ~1070 字符）。
    要动请先确认摘录短了之后模型不会为了看细节再调一次。
